The degree/roman-numeral view and the ChordPro parser changes from the batch. Findings marked "verified" were reproduced by running the code directly with Node.

## Checklist

- [ ] **[high]** `src/lib/chordpro/parser.js:9, 69-87` — the new sectional-key branch is unreachable: `KNOWN_META` contains `'key'`, so the generic meta branch at line 69 always matches and `continue`s **before** `if (directive.name === 'key')` at line 73. Verified: `KNOWN_META.has('key') === true`. Consequences: modulation tracking (`sectionKeyContexts`) is dead code with no consumers; a second `{key: G}` **overwrites** `meta.key` (last-wins instead of first-wins); every chord resolves against the last key. Violates `features/music-theory.feature:110` and `:134`.
- [ ] **[high]** `src/lib/degreeResolver.js:68-100` — `qualityForDegree` builds the triad one scale degree too close: `thirdIdx = degree + 1` / `fifthIdx = degree + 2` select the second and fourth above the root (a step-sum of 1–3 semitones), never a third + fifth. Verified: in C major, degree 1 → `{third: 2 semitones, fifth: 4}` — no branch for `fifthInterval` 7/6/8 can ever fire, so the result is **always `'power'`**, which formats as an uppercase numeral. Trigger: key C + `Dm` → shows **"II"** instead of "ii"; key G + `F#dim` → **"VII"** instead of "vii°"; a minor-key tonic always renders **"I"** while `features/music-theory.feature:76` explicitly demands "i, not I". Every numeral in the app is wrong.
- [ ] **[high]** `src/lib/degreeResolver.js:138-150` — standard ChordPro minor keys don't parse: `parseKeyContext('Am')` returns `null` (verified by running it) because there is no `m`-suffix handling and `'Am'` is not a note name. The repo ships songs with `{key: Em}`. Trigger: open any minor-key song → "Show roman numerals" → every chord dimmed with **no numeral**, under a toggle that says "Showing: Roman numerals".
- [ ] **[medium]** `src/pages/SongDetail.jsx:341-363` + `src/components/notation/ChordProRenderer.jsx:31-39` — `degreeMap` is built from `parsed` (original chords, original key) but the renderer receives `transposed` and looks up `degreeMap[segment.chord]`; degree view also skips `applySubstitution`. Trigger: key C chart `C-Am-F-G`, degree view on, transpose +2 → chords become D/Bm/G/A; only `G` hits the map and displays **"V"` (its old key-C value) though G in D major is IV — a *wrong* numeral, others blank. Violates `music-theory.feature:69` and `:93`.
- [ ] **[medium]** `src/lib/degreeResolver.js:113-132, 159-177` — the concrete chord quality is never reflected: `resolveDegree` passes only the **scale** quality to `formatRomanNumeral`, so spec'd `E7 → I7` (`music-theory.feature:79-85`) renders plain `I`. Also `rootToDegree` returns `null` for any non-diatonic root (`Eb` in C, `Bb` in G) → borrowed chords show **no numeral** while `progressions.js` catalogs `bIII/bVI/bVII/bII` patterns the resolver can never produce.
