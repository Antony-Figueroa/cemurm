Frontend state bugs in the public library and organizations screens from the batch.

## Checklist

- [ ] **[medium]** `src/pages/PublicLibrary.jsx:147` vs `src/components/moderation/ReportDialog.jsx:45` — on success the parent calls `setReportTarget(null)` before the dialog's `setSubmitted(true)` lands, so `ReportDialog` unmounts and the confirmation screen **never displays**. Trigger: `/library` → Report → reason → checkbox → Submit → nothing happens visually → the user resubmits → "Already reported." Both possible flush orderings end with the dialog unmounted, so the `submitted` branch is dead in this wiring.
- [ ] **[medium]** `src/pages/PublicLibrary.jsx:134` — `alreadyReported` is not reset when `reportTarget` changes, and is written only after **four sequential** awaited `checkReported` round-trips. Trigger: report entry A → close → open entry B immediately → B's dialog shows A's reasons as "Already reported" (wrongly disabled); two overlapping `openReport` calls can interleave so the older call's `setAlreadyReported` lands last, leaving permanently wrong state until reopen. No cancellation guard, no loading indicator. Also bounded N+1: a single `.in('reason', …)` query would replace the loop.
- [ ] **[medium]** `src/pages/PublicLibrary.jsx:73` vs `0015:320` — self-report is blocked **only** by `disabled={Boolean(mine)}` in the component: `reports_insert_self` only checks `reporter_id = auth.uid()` and `consolidate_report` does not exclude self-reports. Any user with a live entry can open a moderation case against their own entry via direct PostgREST calls, polluting the moderator queue. Component guard with no data-layer guard.
- [ ] **[low]** `src/pages/Organizations.jsx:216` — `handleLeave` refreshes memberships but not the repertoire list: after `leaveOrganization` only `loadMemberships()` runs, so `visibleSongs` still contains the departed org's songs. Trigger: leave an org while holding an elevated role → "Repertoire scopes" still shows its songs (promote/demote buttons visible) until a full reload; clicks then fail server-side.
- [ ] **[low]** `src/components/layout/AppLayout.jsx:9` — the "Moderation" nav link is shown to **every** signed-in user; non-moderators get the "Only system-appointed community moderators…" message at `/moderation`. Harmless (server RLS holds everything). *Not sure* whether showing it to everyone was a deliberate discoverability choice.
