## Checklist

- [ ] **[critical]** `supabase/migrations/0016_org_repertoire_model.sql:122` — `songs_select_system USING (org_id is null)` treats every `org_id IS NULL` song as a system-catalog row, but the client creates personal songs with `org_id` unset (`addSong` inserts only `{created_by, title}`, `src/lib/songs.js`). Additionally `listSongs` has no `created_by` filter. Trigger: any authenticated user opens `/songs` → the list contains titles/artists of **every user's** personal repertoire. Impact: platform-wide metadata leak + corrupted main screen. Chart bodies stay owner-only via 0003, but catalog metadata does not.
- [ ] **[critical]** `supabase/migrations/0019_rehearsal_workflow.sql:184` vs `0018_service_planning.sql:344` — `private.display_name_for(uuid)` is created twice, both with plain `create function` (no `or replace`). Trigger: fresh full-chain reset `0001 → 0019` aborts at 0019:184 with SQLSTATE 42710. Impact: the entire rehearsal-workflow migration (tables, policies, RPCs after that line) never applies on a clean environment.
- [ ] **[high]** `0016:221-230 + 479-506` — `event_participants.org_id` is unconstrained: the participant INSERT policy only checks "I organize this event". Trigger: attacker creates event E, inserts `(E, victim_org)`, calls `event_repertoire(E)` → returns `title, artist, genre` for the victim org's entire private and branch repertoire, bypassing `songs_select_org` / `songs_select_branch`.
- [ ] **[high]** `0016:166-179` — `songs_update_source_org` has no `WITH CHECK`, so only the old-row `USING` applies to `source_org_id`. Trigger: an elevated member of the source org updates a promoted song setting `org_id`/`branch_id` to any other org → plants content into another tenant's private repertoire (readable there, undeletable by them).
- [ ] **[high]** `0016:309-325` — `event_setlists_update_organizer` `WITH CHECK` only re-checks "new event not concluded". Trigger: an organizer PATCHes their row onto a **different** organizer's non-concluded event (slot hijack) or sets a foreign `org_id`.
- [ ] **[medium]** `0014_seed_scale_catalog.sql:29-31` — three Harmonic Minor modes are wrong (verified programmatically against parent `[0,2,3,5,7,8,11]`): `Locrian #6` is not a rotation of the parent, `Ultralocrian` is an exact duplicate of *Altered*, `Ionian Augmented` is an exact duplicate of *Lydian Augmented*. Degree/scale resolution against these rows returns wrong semitone sets.
- [ ] **[medium]** `0014:41` — `Melodic Minor (ascending)` duplicates root `Melodic Minor` at rotation 0 with identical intervals → two indistinguishable entries in the catalog read surface.
- [ ] **[medium]** `0018:95-147, 299-303` — no write path exists for `services` / `service_blocks` anywhere in `0001..0019` (no create-service RPC, no INSERT, nothing sets `services.status`). Consequences: write policies are dead, no block can ever be created for `reorder_service_blocks` / `assign_musician`, and `services.status = 'completed'` is unreachable, so every `status <> 'completed'` guard and scenario 16 are dead.
- [ ] **[medium]** `0018:335-341` — `block_interval` coalesces NULL/0 `time_budget` to a zero-length interval `[x,x)`, and exclusive-bound intersection is never true for it. Trigger: budgets not filled in, two blocks at the same offset with the same musician → no overlap warning, which is exactly what scenario 8 exists to catch.
